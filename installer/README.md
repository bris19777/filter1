# מתקין הכל-באחד ל-Windows

קובץ התקנה יחיד, `filter1-setup.exe`, שמכיל **הכל**: פייתון פרטי, dnslib,
mitmproxy, שני הסוכנים ותוסף הסינון. אין שום הורדה מהאינטרנט בזמן ההתקנה.
לחיצה כפולה מתקינה גם את שכבת ה-DNS וגם את הפרוקסי, כולל התעודה, המדיניות וחומת האש.

## איך בונים אותו

הבנייה רצה על שרת Windows של GitHub, אין צורך במחשב Windows משלך.

1. דחוף את הפרויקט ל-GitHub.
2. בהגדרות המאגר, תחת **Settings → Secrets and variables → Actions**, הוסף:
   - **Secret** בשם `AGENT_TOKEN` עם ערך הטוקן שלך.
   - אופציונלי, **Variable** בשם `FILTER1_SERVER` אם כתובת השרת שונה מברירת המחדל.
     ניתן לתת **כמה כתובות מופרדות בפסיק**, והסוכן ירשם דרך הראשונה שהרשת מאפשרת
     (ראה "רשת מסננת כמו רימון" למטה).
   - אופציונלי, לחתימת קוד: **Secret** בשם `SIGN_PFX_BASE64` (תעודת החתימה בפורמט
     PFX מקודדת ב-Base64) ו-**Secret** בשם `SIGN_PFX_PASSWORD` (סיסמת ה-PFX).
     אם הם קיימים, הבנייה חותמת אוטומטית את `filter1-setup.exe`. אם לא, נוצר קובץ
     לא חתום (עובד, אך SmartScreen יזהיר). ליצירת ה-Base64:
     `[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx")) | Set-Clipboard`
3. בלשונית **Actions**, הרץ את **Build installer** ידנית (Run workflow), או דחוף תג גרסה כמו `v1.1.1`.
4. בסיום, הורד את הפריט `filter1-setup` שמכיל את `filter1-setup.exe`.

## התקנה על מחשב לקוח

לחיצה כפולה על `filter1-setup.exe`. אם הקובץ **לא חתום**, תופיע אזהרת SmartScreen —
לחץ **More info → Run anyway**. אם חתמת אותו בתעודת OV/EV, האזהרה תיעלם (ל-EV מיד,
ל-OV אחרי צבירת מוניטין). ההתקנה מתקינה את שתי השכבות ומפעילה אותן.

### אם אנטי-וירוס חוסם את ההתקנה

זו תוכנת בקרת הורים גלויה שמותקנת בידי מנהל המחשב, אך היא משנה DNS, מתקינה תעודת
שורש ומפעילה פרוקסי, ולכן הגנות מסוימות עלולות לסמן אותה בטעות. שתי דרכים להקטין זאת:

1. **חתימת קוד** (מומלץ): ראה למעלה. חתימה תקינה היא הפתרון הנתמך לאזהרות SmartScreen
   ולסימון קובץ טרי בעל מוניטין נמוך.
2. **החרגה ידנית ב-Windows Defender** (אופציונלי, על המחשב שאתה מנהל): כמנהל, הרץ
   ב-PowerShell כדי להחריג את תיקיית ההתקנה:
   `Add-MpPreference -ExclusionPath "C:\Program Files\filter1"`
   בטל בעת הסרה עם `Remove-MpPreference -ExclusionPath "C:\Program Files\filter1"`.

### רשת מסננת כמו רימון (הרישום בשרת נחסם)

אם המחשב מחובר דרך רשת "אינטרנט נקי" (רימון וכדומה), היא עלולה לחסום את הדומיין של
שרת הבקרה (למשל `*.fly.dev`), וכך הסוכן לא נרשם והמחשב לא מופיע בלוח הבקרה, גם אם
תעודת ה-mitmproxy כבר מותקנת. שתי דרכים, מהמומלצת:

1. **דומיין ייעודי מאושר:** הצב לשרת דומיין משלך (למשל דומיין רגיל שמצביע לאפליקציה),
   ובקש מרימון לאשר אותו דרך טופס בקשת אתר שלהם. זו הדרך הנקייה, בלי לעקוף את הסינון.
2. **כמה כתובות שרת עם מעבר אוטומטי:** אפשר לתת יותר מכתובת אחת, מופרדות בפסיק, ב-
   `FILTER1_SERVER` בזמן הבנייה, או בשורת `server=` בקובץ `C:\Program Files\filter1\filter1.cfg`
   אחרי ההתקנה. הסוכן והפרוקסי ינסו כל כתובת לפי הסדר וירשמו דרך הראשונה שהרשת מאפשרת.
   כך אפשר להחליף לדומיין מאושר בלי להתקין מחדש. לאחר עריכת הקובץ, השינוי נתפס תוך דקה.

הכלי "מצב filter1 (אבחון)" יראה בדיוק אם הרישום נכשל ומה השגיאה, ואיזו כתובת שרת פעילה.

לאבחון מהיר, ראה "מצב ואבחון מקומי" למטה.

## מצב ואבחון מקומי

כדי לדעת למה משהו לא עובד, פתח **תפריט התחל → filter1 → מצב filter1 (אבחון)**, או
הרץ `filter1-status.bat` מתיקיית ההתקנה. הכלי מציג בעברית, עם סימון תקין/תקלה, את:

- ההגדרות שנמצאו (כתובת השרת ומזהה המחשב).
- האם הסוכן רץ (לפי עדכון אחרון של `status.json`).
- **רישום בשרת** — האם המחשב מוכר לשרת ומופיע בלוח הבקרה, ואם לא, מה השגיאה.
- שרת ה-DNS המקומי (פורט 53), האזנת IPv6, והאם הסוכן שולט על DNS המערכת.
- הפרוקסי (פורט 8080), קיום תעודת mitmproxy, האם היא מותקנת ב-Root, וניתוב הדפדפנים.
- שורות אחרונות מהיומנים.

למשל, אם התעודה מותקנת אך המחשב לא נרשם בשרת, הכלי יאמר במפורש שהבעיה היא בקשר לשרת
(אינטרנט/כתובת/טוקן) ולא בפרוקסי. הדוח נשמר גם ב-`C:\ProgramData\filter1\status.txt`.
הסוכן עצמו כותב `status.json` בכל דקה, כך שהמצב מתעדכן גם ללא הרצת הכלי.

## חסימת אפליקציות VPN (אופציונלי)

חסימת הרצה של תוכנות VPN מוכרות לפי שם קובץ הוצאה מהתקנת ברירת המחדל, כי היא משתמשת
במנגנון Image File Execution Options שאנטי-וירוס מסמן לעיתים קרובות כנוזקה וחוסם את
כל ההתקנה. היא זמינה כשלב מפורש שמריצים אחרי ההתקנה, כמנהל:

- הפעלה: לחיצה ימנית על `harden-apps.bat` → Run as administrator.
- ביטול: לחיצה ימנית על `unharden-apps.bat` → Run as administrator (ההסרה הכללית
  מנקה אותה גם כן).

חסימת הפרוטוקולים של VPN בחומת האש נשארת פעילה בהתקנת ברירת המחדל.

## הסרה

שלוש דרכים, כולן דורשות את **קוד ההסרה** מלוח הבקרה (מאומת מול השרת), ורק אז מסירות
הכל ומחזירות את המערכת לקדמותה. בלי קוד נכון ההסרה נעצרת:

1. **מאותו קובץ התקנה:** הרץ שוב את `filter1-setup.exe`. הוא מזהה שהתוכנה מותקנת
   ומציע: Yes = הסרה, No = התקנה מחדש/עדכן, Cancel = ביטול.
2. **הוספה והסרה של תוכניות → filter1 → Uninstall.**
3. **תפריט התחל → filter1 → הסרת filter1.**

## התקנת גרסה חדשה על גרסה קיימת (עדכון)

הרצת גרסה חדשה של `filter1-setup.exe` על התקנה קיימת עושה עדכון במקום, לאותה תיקייה:

- לפני העתקת הקבצים, המתקין **עוצר את המשימות `filter1` ו-`filter1-proxy`** ואת תהליכי
  ה-Python/mitmdump שרצים מתיקיית ההתקנה, כדי שקבצים בשימוש לא יחסמו את העדכון.
- לאחר מכן הקבצים מוחלפים, המשימות נרשמות מחדש ומופעלות, והתעודה נבדקת מחדש.
- **מזהה המחשב, התעודה וההגדרות נשמרים** (הם ב-`C:\ProgramData\filter1`), כך שהמחשב
  נשאר אותו מכשיר בלוח הבקרה. אין צורך להסיר קודם.

אחרי עדכון, מומלץ להריץ את "מצב filter1 (אבחון)" כדי לוודא שהכל חזר לפעול.

## עדכון אוטומטי מרחוק

הסוכן יכול לעדכן את עצמו בכל המחשבים בלי גישה פיזית. בכל דקה הוא מקבל מהשרת גרסה
אחרונה, כתובת מתקין וטביעת אצבע של תעודת החתימה. אם הגרסה חדשה יותר משלו, הוא מוריד
את המתקין, **מאמת שהוא חתום ושטביעת האצבע תואמת**, ורק אז מריץ אותו בשקט (עדכון במקום).

**אבטחה (חשוב):** עדכון קוד לתהליך שרץ כ-SYSTEM הוא רגיש. לכן:
- העדכון רץ **רק** אם המתקין חתום חתימה תקינה **וטביעת האצבע תואמת** לזו שהגדרת. בלי
  טביעת אצבע, או בכשל אימות, הסוכן מסרב ונשאר בגרסה הנוכחית. כך גם שרת שנפרץ לא יכול
  לדחוף קוד בלי המפתח הפרטי של החתימה.

**הגדרה חד-פעמית:**

1. **תעודת חתימה.** או תעודת OV/EV בתשלום, או תעודה עצמית (חינם) שיוצרים כך במחשב Windows:
   ```powershell
   $c = New-SelfSignedCertificate -Type CodeSigning -Subject "CN=filter1 updates" -CertStoreLocation Cert:\CurrentUser\My
   $c.Thumbprint   # זו טביעת האצבע שתזין בפאנל
   Export-Certificate -Cert $c -FilePath codesign.cer                    # חלק ציבורי
   $pw = ConvertTo-SecureString "PFX-PASS" -AsPlainText -Force
   Export-PfxCertificate -Cert $c -FilePath codesign.pfx -Password $pw   # חלק פרטי (סודי)
   ```
2. **חתימה בבנייה.** הגדר את ה-secrets `SIGN_PFX_BASE64` ו-`SIGN_PFX_PASSWORD` (ראה "איך
   בונים אותו"). כך כל מתקין נבנה חתום.
3. **אמון בתעודה עצמית.** אם השתמשת בתעודה עצמית, הנח את `codesign.cer` בתיקיית `installer/`
   במאגר. הבנייה תצרף אותה, וההתקנה תוסיף אותה ל-Trusted Publishers של המחשב, כך שאימות
   החתימה יעבור. לתעודת OV/EV אין צורך בשלב הזה.
4. **אחסון המתקין.** העלה את `filter1-setup.exe` שנבנה לכתובת נגישה (רצוי דומיין מאושר
   ברימון, למשל אותו דומיין של השרת).
5. **הגדרה בפאנל.** בעמוד הראשי, תחת "עדכון אוטומטי מרחוק", מלא: גרסה (למשל `1.1.8`),
   כתובת המתקין, וטביעת האצבע. שמור. מכאן כל סוכן מיושן יתעדכן תוך דקה.

מצב העדכון מופיע ב"מצב filter1 (אבחון)" ובקובץ `status.json` (שדות `agent_version`,
`latest_version`, `update_state`). לכיבוי, נקה את השדות בפאנל.

## הערות

- **חתימת קוד:** ללא תעודה הקובץ לא חתום ו-SmartScreen יזהיר. הגדרת `SIGN_PFX_BASE64`
  ו-`SIGN_PFX_PASSWORD` (ראה "איך בונים אותו") מפעילה חתימה אוטומטית בבנייה. תעודת
  OV/EV בתשלום היא שמסירה את האזהרה.
- **גודל:** הקובץ גדול, עשרות מגה, כי הוא מכיל פייתון ו-mitmproxy מלאים.
- **טוקן:** הטוקן מוטמע בתוך הקובץ. שמור אותו אצלך ואל תפיץ אותו בפומבי.
